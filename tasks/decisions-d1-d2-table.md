## Restricción que condiciona ambas decisiones

`tools/validate/skill_spec.py` (línea 50) y ADR-0017 aplican un **techo de
`allowed-tools` por `metadata.type`**:

| type           | máximo permitido              | consecuencia práctica                                                        |
| -------------- | ----------------------------- | ---------------------------------------------------------------------------- |
| `audit`        | Read, Grep, Glob              | no puede ejecutar `doctor.py`, `scan_repo.py` ni correr escáneres            |
| `router`       | Read, Glob                    | no puede invocar `tools/workspace-router/run.py` ni escribir `.machineroom/` |
| `atomic`       | Read, Write, Grep, Glob, Bash | puede mutar vía `tools/` o suites                                            |
| `orchestrator` | Read, Grep, Glob, Bash, Write | flujo multi-paso con escritura                                               |

Por eso **el tipo no es una etiqueta cosmética**: cambiarlo obliga a cambiar
`allowed-tools`, y con ello a quitar o mover capacidades. Dos filas de la
recomendación anterior (D2) chocan con este techo y se corrigen más abajo.

**Nota técnica sobre `router`.** Ningún reparto puede declarar `plan-router` con
`metadata.type: router`: el techo `router` deja sólo `Read, Glob`, y ese skill
necesita `Bash` para `tools/workspace-router/run.py` y `Write` para
`status.yaml`. Por eso la opción B usa `plan-continue` como `orchestrator`; `router`
queda reservado a un futuro skill que no ejecute nada.

## Recomendación revisada

- **D1 → B**, con dos matices: `plan-continue` conserva `orchestrator` y el bloque
  de fases; `project-audit` entra como `atomic` (no `audit`), porque el tablero de
  repo escribe `ESTADO.md` y corre scripts. Si no se quiere un `project` de 5
  skills, **A** es el sustituto limpio.
- **D2 → A, con la corrección de `project-machineroom`**: `project-libraries` pasa a
  `atomic` (+Bash), `project-publish` a `orchestrator`, `project-machineroom` se
  queda en `orchestrator`. Sin la corrección, el validador rechaza el cambio
  (techo `audit`) o la skill pierde su operación de escritura.

Ambas decisiones comparten ficheros (`test_catalog_*.py`, `registry.yaml`,
`TAXONOMY.md`), así que conviene ejecutarlas en la misma tanda.
